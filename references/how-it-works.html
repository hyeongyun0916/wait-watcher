How waits-watcher works

A Claude session registers something you are waiting on. A loop on the same machine runs cheap probes every 20 minutes, hands Claude only the waits whose probe changed (and every open wait once an hour), posts to Slack when one is done, and tells the session that registered it. The only store is the board artifact's database.

Flow

Orange: telling the session that registered a finished wait. A running session gets a message on its socket, found by session id. A session that is not running is resumed headless in its own working directory; one that cannot be resumed waits in a queue, retried every tick for up to 24 h and 3 tries.

What keeps running

waits.sh loopA setsid process; its pid is in ~/waits/loop.pid. It dies when the machine or container restarts; start it again with waits.sh start.
claude -p check runStarted by the loop and gone when done. Runs in permission mode auto with a deny list that blocks Slack posting, gh writes, git, kubectl and curl.
claude -p --resumeStarted only for a finished wait whose session is not running. It acts with your access, like the session itself; its report lands in that session's transcript.
