대기 보드는 이렇게 돈다

남을 기다리는 일을 세션이 등록하면, pod 안 루프가 10분마다 확인하고 끝나면 Slack 채널에 알린다. 원본은 대기 보드 아티팩트의 저장소 하나뿐이다.

흐름

어떤 부분이 어떤 모델인가

부분모델언제 도는가하는 일
wait-watcher 세션Opus 5.5사용자가 말할 때만세션 찾기, 대기 등록·다시 대기·질문 답변, 등록 직후 waits.sh check <id>
다른 대화형 세션그 세션 모델그 세션이 필요할 때wait-watcher에 SendMessage로 요청하거나 저장소를 직접 고침
확인 run (claude -p)Sonnet 5.510분마다 1회, 최대 15분열린 대기를 하나씩 읽기 전용으로 확인, 결과 기록, 24시간 지난 보관 항목 삭제, 알림 문장 작성
waits.sh 루프모델 없음항상 (pod가 살아 있는 동안)확인 run 실행, 결과 파싱, webhook 전송, 연속 실패 18회면 경고
대기 보드 페이지모델 없음열어 볼 때저장소를 실시간 표시, 메모·취소·다시 대기·보관·할 일 추가

하루 비용은 대부분 Sonnet 확인 run에서 나온다(약 $30/일, 열린 대기 수에 비례).

계속 도는 것

waits.sh looppod 안 setsid 프로세스. pid는 ~/waits/loop.pid. pod 재시작 시 죽으며, 다시 켤 때는 waits.sh start.
claude -p (Sonnet)루프가 10분마다 띄웠다가 끝나면 사라지는 일회성 프로세스. 쓰기 금지 도구 목록(--disallowedTools)으로 Slack 전송·gh 쓰기·git·kubectl·curl을 막는다.

저장소 (원본)

waits/<id>대기는 w…, 할 일은 t…. 상태 open · done · stuck · cancelled, 보관 시 deleted_at.
meta/status마지막 확인 시각과 "열린 대기 N · 완료 M · 오류 K".
meta/sessions할 일 추가 칸의 세션 목록. 확인 run이 살아 있는 세션으로 맞춘다.
